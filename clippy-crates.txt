# Which crates in the tree expose a function clippy.toml's `disallowed-methods`
# bans: reading the clock; writing, renaming, removing or syncing files.
# `scripts/check-clippy-bans.sh` checks this map against Cargo.lock and
# fuzz/Cargo.lock, and fails until every crate in them is listed here, so a
# new dependency's clock reads and file writes are looked for when it arrives,
# not after a reviewer happens to spot one.
#
# Each crate goes in one of these sections:
#
#   [ban]                 functions of the families, by path. Each must also
#                         be in clippy.toml's disallowed-methods.
#   [allow: <reason>]     functions (paths) or whole crates (names) of the
#                         families that are deliberately not banned. Like an
#                         #[expect], each says why.
#   [none: <reason>]      crates whose API has no such function, including
#                         the types it returns.
#   [indirect: <reason>]  crates nota's code can't name: no nota crate
#                         depends on them directly, and no direct dependency
#                         re-exports them. The check fails if one becomes a
#                         direct dependency, so it's classified then.
#
# A crate can have [ban] and [allow] paths both, but a crate under [none] or
# [indirect] has no paths. Names are as Cargo.lock spells them; paths use the
# crate's name in Rust (`jiff_core`, not `jiff-core`). A new version of a crate
# already here isn't re-checked: when a bump adds API, review it as you would
# a new crate. Changes here count as check changes (scripts/check-weakened.sh).
